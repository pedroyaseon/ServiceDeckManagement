# Contribuindo

1. Leia `IMPLEMENTATION_PLAN.md` e `AGENTS.md`.
2. Abra uma issue para mudanças de escopo ou arquitetura.
3. Use uma branch curta e descritiva sem `agent` ou `codex` no nome.
4. Mantenha cada PR com um único objetivo verificável.
5. Inclua testes, documentação e análise de segurança proporcionais ao risco.
6. Execute as verificações locais antes do push.
7. Não envie arquivos de `runtime/`, segredos, caminhos pessoais ou artefatos.

Commits devem ser pequenos, técnicos e descrever o resultado. PRs começam como
rascunho e só podem ser fechadas após os gates definidos no plano.
